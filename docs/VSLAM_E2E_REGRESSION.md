# Go2 真 VSLAM 全链路导航回归

这套回归验证从视觉建图到重启定位、闭环导航和跟踪恢复的完整链路。全局定位和路径规划使用相机、IMU、RTAB-Map 位姿及其占据栅格；局部避障还使用模拟距离扫描。MuJoCo 真值位姿仅用于评分，不用于校正视觉定位或规划全局路线。底层 RL 步态仍使用原有模拟本体感知与地形观测，并非整个系统完全不接触仿真状态。

## 测试流程

`run_vslam_e2e_benchmark.sh` 自动执行两个相互独立的进程阶段：

1. 建图阶段在家庭环境中按传感器位姿探索，建立并保存 RTAB-Map 数据库。
2. 建图进程完全退出后，定位阶段以只读方式重新加载该数据库。
3. 依次导航到客厅、卧室、厨房和起点。
4. 到达卧室后遮挡 RGB 和深度图 2.5 秒，再主动转动搜索并测量重定位时间。
5. 汇总目标到达、家具碰撞、回环、漂移、返回误差和重定位结果。

入口使用单实例锁；重复启动会立即退出，避免多组 ROS 发布者污染相机、TF、数据库和测试报告。
RTAB-Map 在独立进程组中运行；退出时先等待数据库刷新，超时才升级终止信号，避免残留节点污染下一次回归。

建图路线和通过阈值位于 `deploy/deploy_mujoco/configs/vslam_e2e_benchmark.yaml`。单个探索目标连续 45 仿真秒没有明显接近，或视觉跟踪反复丢失超过预算时会明确失败，避免定位异常时无限转圈或靠短暂假恢复刷新超时。

## 运行

依赖 ROS 2 Jazzy、`rtabmap_ros`、RViz2、MuJoCo 和本项目 Python 环境。当前工作站可直接运行：

```bash
cd /home/user/下载/go2_rl_gym
./run_vslam_e2e_benchmark.sh
# 相同传感器、物理和控制流程，省去第三视角窗口：
./run_vslam_e2e_benchmark.sh --headless
```

回归默认不启动 RViz，以减少渲染负载；MuJoCo 窗口仍会显示。普通交互式 VSLAM 使用：

```bash
./start_go2_vslam.sh --new-map
./start_go2_vslam.sh --localization
```

## 结果文件

- `maps/vslam_e2e_benchmark.rtabmap.db`：持久化 RTAB-Map 数据库。
- `reports/vslam_e2e/mapping.json`：建图阶段原始指标。
- `reports/vslam_e2e/localization.json`：重启定位阶段原始指标。
- `reports/vslam_e2e/report.json`：机器可读的总报告。
- `reports/vslam_e2e/report.md`：便于阅读的 PASS/FAIL 报告。
- `reports/vslam_e2e/{mapping,localization}.rtabmap.log`：分阶段的 RTAB-Map 日志。
- `reports/vslam_e2e/*.trace.json`：每 0.25 仿真秒记录的评分位姿、匹配点数与航点进度。
- 阶段 JSON 的 `contact_events`：每次接触事件的起始时间、起始力、几何体名称、评分位姿及当时导航指令/状态；控制诊断也保存在轨迹中。接触信息仅用于评分和离线诊断，不反馈给导航。
- `reports/vslam_e2e/*.sensors/`：跟踪丢失时的 RGB 截图及米制深度数据。
- `reports/vslam_e2e/*.map.npz`：阶段结束时收到的 RTAB-Map 占据栅格。
- `logs/rtabmap.log`：普通交互式启动的日志。

如果建图失败，脚本会跳过定位阶段并仍生成报告，退出码为非零。数据库和报告属于运行产物，已由 `.gitignore` 排除。

## 通过标准

- 客厅、卧室、厨房和起点全部到达。
- 家具碰撞为 0。
- 返回起点位置误差小于或等于 0.25 m。
- 最终航向误差小于或等于 10°。
- 人为遮挡导致跟踪丢失后 5 秒内恢复。
- 至少检测到一次回环。
- 保存数据库后重启仍能完成只读定位导航。

报告中的“回环”计数包含 RTAB-Map 接受的视觉回环和空间邻近地图匹配事件；定位模式会多次匹配保存地图，因此它不是机器人绕房间的圈数。

## 真实性边界

`VslamE2EBenchmark.update_control()` 不读取 MuJoCo 真值。真值只在 `observe()` 中计算位置和航向漂移、目标真实误差以及碰撞评分。评分器可在漂移超过安全界限时终止已经无效的测试，但不会校正 RTAB-Map 位姿。

这意味着报告失败是有效结果：它表明当前视觉里程计、回环或重定位尚未达到门槛，而不是由固定地图或真值位姿掩盖问题。

## 传感器与回归修正

- 相机、深度、内参、IMU 与 `/clock` 使用同一个仿真采样时间；RTAB-Map 和 RViz 开启 `use_sim_time`。渲染耗时不再变成传感器间的时间偏差。
- RGB、米制深度和标定打包为单条可靠传输的 `RGBDImage`。分开发送三个 best-effort 话题再 exact-sync 会因任意一路丢包丢弃整帧，造成有效匹配点仍很多、里程计却长时间收不到图像的假性跟踪丢失。原始图像话题仍保留用于可视化。
- 机器狗的视觉里程计和图优化保留上下起伏、横滚与俯仰。导航栅格仍是二维，不能因此把相机运动也强制压成二维。
- RGB-D 使用三维对应点的几何验证，并开启 F2M 局部束调整。旧的平面运动限制与关闭局部优化的配置不再作为默认值。
- 位姿或 TF 超过 0.5 仿真秒未更新时，导航停止使用该位姿。迟到的旧状态消息不能覆盖较新的跟踪丢失状态；图优化的航向修正会传给导航。
- 保存地图的订阅使用 transient-local，避免错过定位节点提前发布的静态地图。定位阶段须收到地图并产生保存地图匹配事件后才启动目标导航。
- 跟踪恢复先通过陀螺仪返回最后有效视角，再进行有界扫描。卧室门口航点的到达范围不再重叠，厨房回转点避开垃圾桶旁的狭窄位置。
- 若视觉丢失时近处物体填满画面，恢复前两秒可先以 `0.15 m/s` 小幅后退；必须同时测到前方近物和后方足够的扫掠空间。相机主动遮挡期间不移动，原来的恢复超时不延长。
- 建图返程对已经观测到的目标使用 RTAB-Map 栅格 A* 绕行；不再只向终点直走、反复顶在电视柜旁。未知区域仍依靠实时传感器探索，不读场景几何构造全局地图。
- 栅格地面分类改为点云法向量分割，取消固定全局高度分界。实测固定 `-0.42 m` 虽能标出书，却会在高度漂移后将大片地面标成障碍。当前在重力对齐的局部坐标系中区分水平面和竖直表面，近地距离扫描补充低矮物品的局部避障；仍需测试多层地形，不能据此宣称已解决所有三维通行问题。
- 保存地图的节点先验误差使用 `0.03 m`，不再假定整张地图精确到 `0.001 m`；保留图优化的三倍标准差错误检查，开启鲁棒优化并关闭冗余的按时间邻近连接。不会通过关闭匹配检查来强行接受重定位。
- 定位时每轮只比较一个邻近历史路径，避免同时引入起点附近多条相互冲突的重复路径约束。视觉几何验证和图误差检查仍开启。
- 局部导航在 `BLOCKED` 状态收到新的原地转向请求时，重新检查侧移、前移或后退的实测空间；不会因为旋转扫掠空间仍不足而永久停住，也不会跳过旋转安全检查。
- 家庭 VSLAM 模式使用地面基准以上 `0.04 m` 和 `0.32 m` 的两层模拟距离扫描，修复只扫描机身高度时看不到低矮物品的转身盲区。低层高度须与平地跨越阈值一致：原 `0.05 m` 加上地毯的 `0.024 m` 基准后，会从 `0.07 m` 高的书本上方扫过。普通楼梯模式仍保留原扫描配置，不把所有可跨越台阶当作墙；两层扫描也不等同于完整真实多线激光雷达模型。
- 家庭 VSLAM 的零接触导航将 `max_step_up` 设为 `0.04 m`，让局部避障绕开书本等物品；否则粗糙地形步态仍会把已检测到的物品当作可踩台阶。普通楼梯模式的 `0.18 m` 跨阶上限不变。这是室内平面导航模式，不应直接用于爬楼梯。
- 平地模式通过 `planar_obstacle_check` 同时检查距离回波的连续坐标和高程栅格。记录轨迹复现显示：14 cm 玩具块能落在 10 cm 高程网格的横向采样间隙中，仍进入实际通行宽度。新增检查使用原通行宽度，不移动物体、不扩大碰撞几何；候选绕行方向也使用此检查，普通跨阶模式默认关闭。
- 同一平地模式对最终速度指令执行 `0.75 s` 恒定速度/角速度的矩形扫掠检查，覆盖后腿和侧向运动，而不只检查机身前方。若转弯会擦物，选择通过检查的减小转速或平移指令；没有安全候选则停下。使用原 `0.39 m × 0.20 m` 半长/半宽，接触关节姿态仅作离线验证。该短时运动预测不等同于带执行误差保证的全身碰撞规划，真实动态仍需实跑验收。
- 回归的相机运动限速先施加到候选指令，再做扫掠检查。此前先验算弧线再裁剪角速度，会改变实际弧线，甚至使原安全轨迹变成碰撞轨迹；单测包含这一反例。逃离候选同样受限速约束。
- 对带有目标航向的定位目标，在距离目标 `0.45 m` 内先对齐航向，再完成最终位置靠近（进入阈值 `10°`、退出阈值 `4°`）。不再先斜着挤进狭窄终点、到达后才尝试转身。此过程使用请求中的航向和视觉位姿，照常经过扫掠保护，不提前标记到达、不改变 `0.15 m` 导航容差或 `0.25 m` 真实误差标准。
- 返回位置按最终转向对齐完成后的真值评分，而不是到达标志首次触发时的位置。
- 视觉栅格规划不再把被占据的目标替换成到达容差以外的空闲格；评分也核对每个目标的实际位置误差，而不是只数“到达”标志。
- 高层导航速度反馈改读视觉里程计，而非 MuJoCo 世界速度。距离路径目标小于 `0.40 m` 时使用限速的位置误差反馈完成精确靠近，避免 PPO 围绕小目标反复转向；底层仍为 RL 步态，指令仍经过原有地形安全检查。该末端控制是显式反馈控制，不宣称是新训练出的 RL 能力。
- 原场景的纯色表面和密集重复棋盘格会导致缺少特征或误匹配。家庭场景加入固定的墙面、地面和家具表面纹理；家具位置、几何尺寸和碰撞属性保持不变。此场景改善了视觉可观测性，但不代表无纹理环境已得到解决。
- 回归默认使用独立 ROS domain 73，可通过 `GO2_BENCHMARK_ROS_DOMAIN_ID` 覆盖；直接启动也有 domain 级单实例锁。报告在退出窗口前写出，避免窗口清理阻塞丢失测试结果。
- 每次运行前将旧报告、轨迹、地图快照、传感器截图和分阶段日志移到 `reports/vslam_e2e/history/`，避免多轮诊断产物混在一起。

所有通过阈值保持不变。原无纹理场景的失败和纹理场景的结果应分别看待，不能把场景改进归功于纯算法提升。
