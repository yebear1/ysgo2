# Go2 EDU / TX1：无实物阶段的准备与复核

本轮只修改开发电脑上的代码，没有部署、连接机器狗或安装 TX1 软件。
目标是提前验证公共导航逻辑、指令仲裁与故障处理，保留 EDU 原厂底层运控。
连接和单轴低速测试仍按 [第一阶段指南](GO2_EDU_TX1_BRINGUP.md) 分步进行。

## 可重复运行的离线检查

在仓库根目录，用已有 Python 3.8+ 开发环境运行。公共导航需要 NumPy 与 OpenCV；
单轴 EDU 工具和指令仲裁模块本身只依赖标准库，实际连接时才导入 SDK。
这里不提供 TX1 安装命令；目标板的系统和二进制依赖尚未确认。

```bash
python deploy/navigation/verify_offline.py --output outputs/go2-offline-prep
```

已具备本仓库 MuJoCo、Torch、PyYAML 等仿真开发依赖时，可同时复核旧链路：

```bash
python deploy/navigation/verify_offline.py --with-mujoco --output outputs/go2-offline-prep
```

检查入口不初始化 DDS，不启动 ROS，也不发送网络运动命令。
输出包括各项日志、`verification.json`、每个被测源文件的 SHA-256，
以及 `mock/report.json` 和逐控制周期的 `mock/trace.jsonl`。
退出码非零表示有检查失败，不能只看报告文件是否生成。

Mock 的 21 个场景包括：0°、−30°、30°、60°、180° 起步的穿门往返；
本体断流、定位过期、地图未匹配、扫描缺失/非法/覆盖不足、前方障碍、
使能释放、急停输入、人工零速度接管、发送失败/异常/延迟、停止无回复、时钟域和地图身份错误。
故障测试在运动中注入问题，再恢复正常输入，检查是否在未重新使能时误续跑。
停止无回复的预期是明确报告失败；它不要求假机器人已经停下，更不算物理停机成功。

**Mock 提供理想地图位姿，模拟的是二维运动和扫描，不运行视觉重定位、步态或 DDS。**
五个朝向通过不能替代此前真实 RTAB-Map 保存地图的朝向回归。该门宽 1.8 m，
也不能作为“机身刚好能通过”的狭窄通道验证。既有几何测试另行检查窄通道和矩形扫掠。
本轮未重跑完整家庭场景 10 组长时 VSLAM 矩阵。

## 公共代码与平台边界

`deploy/navigation/grid_navigation.py`、`terrain_navigator.py` 和
`high_level_nav_policy.py` 保存原有公共算法；原仿真目录保留兼容导入。
MuJoCo 射线建图与路径绘制仍在仿真适配层。终点朝向控制移至 `terminal_control.py`。
旧默认仿真链路保留其行为；新的 `runtime.py` 不依赖 MuJoCo、ROS、SDK 或 Torch。

新的低速运行链路为：地图与已验证位姿 → A* 路径/终点控制 → 指令仲裁 →
限速后的矩形运动扫掠检查 → 注入的速度出口。
`EduSportSink` 调用注入客户端的 `Move/StopMove`；`MujocoVelocitySink` 把指令交给仿真步态环。
本轮并未把旧 RL 电机控制入口改成 EDU，也未在新链路启用学习策略。
新链路遇到阻塞会停下等待重新下发目标，尚不自动绕开突然出现的障碍。

新链路的到点判定以请求坐标为准，默认容差 0.15 m；若指定终点朝向，还要进入 4° 范围。
请求点落在障碍膨胀区时拒绝任务，不替换成附近栅格中心并报成功。
终点直线修正也必须经过已观测的可通行地图单元。已有地图路径算法默认行为不受该选项影响。

`contracts.py` 定义相机、IMU、地图位姿、扫描、本体状态与速度请求的数据格式：

- 距离/位置用米，速度用 m/s，角度用弧度，角速度用 rad/s。
- 位姿必须在 `map`，速度和扫描必须在 `base_link`；身体坐标约定前向 +X、左向 +Y、逆时针 +yaw。
- `map_id` 标识同一个地图会话；地图替换、重建或重新定位坐标系重置时换 ID，并取消当前任务。
- `matched` 必须来自定位器已验证的保存地图匹配，不能用“里程计正常”或“地图加载成功”替代。
- 所有时间戳必须先转到同一单调时钟；不得把接收时刻覆盖到重复/旧样本上来伪造新鲜度。
- `RobotState.sequence` 是去重并展开回绕后的递增序号；`enabled` 是操作者使能，不能直接取电机上电状态。
- 相机/IMU 格式是将来真实定位器的输入边界，尚未接入任何具体相机或雷达驱动。

## 仲裁与停止语义

每个控制周期都调用 `MotionGateway.dispatch`；优先检查本体状态与急停，再处理人工指令，
最后才允许已使能、同一任务代次的自主指令。人工零速度也能接管；旧自主请求在接管后失效。
默认限速为 X/Y 各 0.10 m/s、yaw 0.20 rad/s，先限速再检查扫掠，之后不重新改变速度比例。

默认有效期：本体状态 0.20 s、扫描 0.20 s、地图位姿 0.25 s、速度请求 0.15 s。
完成处理后会再次检查数据年龄；发送返回后若速度请求已超时，也停止并锁定故障。
测试中的延迟是可返回的同步调用，不是 SDK 永久卡死。

急停、传输故障、时钟倒退/混用和序号错误会锁定故障。
解除需显式调用 `reset_fault`，并提供新鲜、已撤销使能、无急停的本体状态，且停止请求得到回复；
随后仍需新的目标和使能。普通断流/障碍停止也撤销自主使能，不自动续跑。
单进程锁只序列化本进程的发送，不能阻止另一程序或遥控器同时控制机器人。

`go2_edu_bringup.py pulse` 已接入该公共出口。它保留释放后重新按住 R1+A 的使能过程、
模式核对、摇杆/倾角检查和最多 2 秒的短脉冲限制。
**只有这一人工监护的首阶段短脉冲**显式允许没有扫描；自主导航始终要求有效扫描。
扫描必须覆盖周向，最大角间隙不超过 16°；缺失、NaN/Inf 或无效值默认拒绝运动。
实际传感器的无回波语义、遮挡和安装外参需后续验证，不能直接把所有无效值填成最远距离。

停止会最多尝试 3 次；已回复停止且其后未发送新运动时，不反复发送。
`transport_ok` 只表示接口返回成功，`physical_stop_verified` 始终为 false。
这不是独立看门狗：主循环不再执行、SDK 永久阻塞、进程被杀、断电或网络故障时，
Python 无法保证物理停机。必须在实物阶段验证底层超时、独立停止手段和实际停车距离。

## 在现有仿真中使用公共入口

`deploy_go2.py` 增加了可选 `--shared-navigation`，需同时启用 `--ros2-vslam`、
有效的周向扫描和现有 RTAB-Map 配置。它与 `--vslam-benchmark-phase` 互斥。
在已按仓库 VSLAM 指南启动 ROS/定位器的开发环境中，给原仿真命令追加这个选项即可。

公共入口从 VSLAM 读取位姿与原始时间戳，不用 MuJoCo 真值补缺失位姿。
可用原来的 RViz 目标或编号目标；收到新目标后，等待已验证位姿，再使能一次。
保护停止后需要重新下发目标。键盘运动/停止或非零手柄输入取消自主任务；松开不会恢复旧路线。
仿真重置会销毁该导航会话，避免沿用旧时钟、任务和使能状态。
本轮验证了适配层、MuJoCo 几何和旧回归；未把此可选入口宣称为整套 RTAB-Map 实时闭环已验收。

## 实物到位后仍要做的事

按第一阶段指南先采集 TX1 信息，再确认 EDU 模式与网络、只读传感器、低速单轴控制。
相机/雷达型号确定后实现时间转换与外参适配，用实录数据复核扫描覆盖与地图匹配。
检查真实矩形包络、负载、步态侧摆和停车距离后再设运动限制。
目前公共新入口只针对平坦室内；没有下坠检测，不用于台阶、坑洞或任意地形。
TX1 的依赖安装、原生运行、感知帧率和实际控制时延均未验证。
